# Reproducing the COMPASS analyses

This is a **source-only** repository as initially prepared. The full data-derived analyses are not reproducible from this checkout alone. The frozen inputs and analysis outputs remain on the originating workstation pending provenance and redistribution review.

## Required files (exact relative paths)

| Path | Role | Release status |
| --- | --- | --- |
| `data/frozen/feature_set_v3/feature_set_v3_structure_core_final.csv` | Corrected v1.1 labels + 15 structural predictors | Not included |
| `data/grouping/stage07/fold_assignments_v1.0.csv` | Fixed fold/group membership | Not included; labels stale |
| `results/stage09_4F/frustration_features.csv` | 12 derived frustration predictors | Not included |
| `results/stage09_v2/rf_fold_metrics.csv` | Audit-only historical baseline comparison required by current scripts | Not included |

Although the fourth file is a historical reference (not a predictor), the current evaluation and ablation scripts **require** it during their input audit. Its historical results may differ from scikit-learn 1.7.2 results; use the new structural-core results as the comparison in a consistent environment.

For higher-level diagnostics, additional files generated by the ablation scripts are required, particularly `results/stage09_4F/group_ablation/{selected_hyperparameters.csv,oof_predictions.csv}`. The extractor also needs its structure manifest, extracted structures, and Frustratometer/AWSEM installation; see the extraction script.

## Environment

The reported Stage 09.4F evaluation was run with Python 3.10, scikit-learn 1.7.2, seed 42. `requirements-analysis.txt` specifies the principal analysis dependencies but is **not** a tested, fully pinned lockfile. Earlier stage-specific requirements are retained under `requirements/historical/`. The frustration extractor separately requires Python `frustratometer` 0.3.2, its compiled/model dependencies, and compatible input structures.

```bash
conda create -n compass python=3.10 -y
conda activate compass
python -m pip install -r requirements-analysis.txt
python -m compileall -q Scripts
```

## Run model comparisons

After independently providing the required files under the paths above:

```bash
python Scripts/stage09_4F_evaluate_frustration.py --audit-only
python Scripts/stage09_4F_evaluate_frustration.py --n-iter 80 --n-jobs 4 --seed 42
python Scripts/stage09_4F_group_ablation.py --n-iter 80 --n-jobs 4 --seed 42
python Scripts/stage09_4F_targeted_ablation.py --n-iter 80 --n-jobs 4 --seed 42
```

Outputs from these commands are written to `results/stage09_4F/{modeling,group_ablation,targeted_ablation}/`. The scripts retrain and tune models and can require substantial CPU time.

For the reconstruction audit and held-out permutation importance after group ablation:

```bash
python Scripts/stage09_4F_reconstruction_audit.py
python Scripts/stage09_4F_permutation_importance.py
python Scripts/stage09_4F_feature_correlations.py
```

## Data-integrity checks

1. All three principal input tables must contain exactly **181 distinct** accession IDs.
2. The corrected frozen label table must contain **73** positives.
3. Use the fold file's **accession, homology fold, and 30% cluster only**; its `binary_label` is outdated (64 positives).
4. The fold assignments must contain **five** outer folds and the train/test group sets must be disjoint.
5. The 15 structural and 12 frustration predictors must have no missing or non-finite values.
6. The evaluation script writes SHA-256 checksums of its input files to `input_audit.json` in the modeling results directory.

## Validation status

All 36 source Python files passed syntax parsing in the release-preparation environment. The full modeling pipeline has **not been rerun** in a fresh environment from this checkout because the frozen dataset and generated features were not supplied. The existing result table in the repository is a user-provided consolidated summary, not an independent rerun.
